## 1. 事故时间线

- **14:22** 内部演示环境（IP: 10.42.18.7）研究任务开始堆积，平均完成时间从 45 秒上涨到 12 分钟

- **14:48** 工程师误判为"DDG 全局故障"，决策切换备用搜索 → 但备用未配置

- **15:30** 团队识别真实原因：内部演示发了一个推文，演示 IP 单点请求量从 ~50/h 飙到 ~3000/h，触发 DDG 反爬封禁
- **16:00** 紧急上线请求频率限流（令牌桶 10/秒，5 并发）

- **18:05** 完全恢复，事故关闭

## 2. 根因 (root cause)

**根因**：DDG 是免费公共服务，对单 IP 高频请求有反爬封禁（无明文文档，约 1500 次/小时阈值）。
项目原假设是"内部低频测试场景"，没有任何客户端限流。

**直接触发**：内部 X 推文带来 60× 流量峰值；事故 IP 是固定的演示机，被识别为爬虫。

## 3. 修复措施（已落地）

### Fix 1: 客户端令牌桶限流
在 `src/tools/search_tool.py` 增加 `token_bucket(rate=10/s, burst=5)`，所有 DDG 请求经过限流。

### Fix 2: 失败重试 + 指数退避
DDG 返回 5xx 或限流时，重试 3 次，间隔 1s、2s、4s。

### Fix 3: 备用搜索通道
配置 Brave Search API 作为热备，env 里加 `SEARCH_FALLBACK=brave`。
触发条件：DDG 连续失败 3 次 → 切 Brave。

### Fix 4: 监控告警
新增指标：
- `dr.search.success_rate` （目标 > 95%）
- `dr.search.latency_p95` （目标 < 3s）
- `dr.research.completion_time_p95` （目标 < 5min）

## 4. 没有立即修复的项

- **完整搜索缓存层**：同一 query 1 小时内重复请求直接命中缓存。优先级 P2，留到 2026-05。
- **多 IP 出口池**：通过多个出口 IP 轮换，从根本上规避反爬。**风险**：可能违反 DDG ToS，法务驳回。
- **彻底脱离免费搜索**：成本预算评估中，全量上 Tavily 月成本约 ¥2,800（按当前流量）。

## 5. 关键教训（写给 Phase 6 之后所有迭代）

1. **任何外部免费服务都不应视为高可用**：DDG / Wikipedia / ArXiv 都可能因反爬限流
2. **限流应该是默认行为**：而不是"等出事再加"
3. **演示环境必须有独立监控**：内部演示和正式生产不在一个告警通道
4. **备用通道要预先配置**：等出事再启用太迟
